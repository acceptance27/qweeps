# QWEEPS visual lessons

When changing lesson pedagogy or authoring new Manim explanations, read
`../src/assistant/visual/teaching_skill/qweeps-visual-teaching/SKILL.md` and the relevant
visual-reasoning, 3Blue1Brown studies and failure-prevention references.

The user accepted the Python, ALU and world-generation demonstrations. Preserve
them while improving infographics. The observed infographic defect is moving
labels without a relationship the viewer can infer. Choose comparisons, grouping,
concrete consequences, changing reference frames or other fitting visual operations;
do not fix it with more narration, generic arrows, or a mandatory beat count.

Before a long native render, probe the actual Manim CE runtime. Use the skill's
`render_review.py` workflow for changed scenes: successful exit, fingerprinted media,
frames from the beginning/middle/end of each beat, then inspect playback and record
what the visual teaches without narration. Check maximum camera zoom, subtitle
regions, clause/reveal timing, forward chapter seeking and rewind on the real host.
File existence or schema validation alone is not completion. Publish only the
reviewed candidate; do not replace a live manifest while audio/render preparation
is incomplete. Read existing requirements before changing renderer dependencies.

The user now prefers live browser scenes with no baking. Read the skill's
`references/live-browser.md` for SVG/GSAP delivery, accurate asset reuse and glyph
tracing. If native Manim is specifically requested, use actual native frames;
name the active renderer honestly. Check transitions, arbitrary rewind,
selection and parameter changes. Fish playback must retain its clip/playhead on
pause and prevent late audio after cancellation. Verify these on the real host.

For history or geographic teaching, compare the actual rendered scene with the
accepted WWI and primary reference lessons before approval. Verify recognizable
locations, named actor roles, visual meaning without narration, and continuity
through changes; record failed frames and improvements. A working renderer or a
plausible storyboard alone does not establish visual quality. For follow-up
questions, use relevant available sources beyond on-screen labels and identify
what evidence was retrieved.
